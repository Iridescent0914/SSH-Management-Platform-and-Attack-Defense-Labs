阶段 2：VM2 配置 SSH 基础安全参数记录

一、阶段目标

本阶段目标是在阶段 1 已完成 OpenSSH Server 安装和 testuser 登录验证的基础上，对 VM2 的 SSH 服务进行基础安全配置，使其满足后续 SSH 管理平台检查、弱口令攻击实验、日志分析和防御验证的需要。

本阶段不进行 Flask 平台搭建，不进行弱口令攻击，不启用 Fail2ban，也不禁用密码登录。PasswordAuthentication 在本阶段保持为 yes，是为了保留后续弱口令暴力破解实验条件。

阶段 2 的主要目标如下：

1. 备份 VM2 的 SSH 主配置文件。
2. 确认 VM2 的 sshd_config 支持 Include 配置片段。
3. 使用 /etc/ssh/sshd_config.d/99-lab-basic.conf 配置实验用 SSH 基础安全参数。
4. 禁止 root 远程 SSH 登录。
5. 保持密码认证开启，用于后续弱口令实验。
6. 启用公钥认证，为后续禁用密码登录和密钥实验做准备。
7. 禁止空密码登录。
8. 设置 MaxAuthTries 为 6。
9. 设置 LogLevel 为 VERBOSE，便于记录更详细的 SSH 认证日志。
10. 使用 sshd -t 检查配置语法。
11. 重启 SSH 服务并确认服务正常运行。
12. 使用 sshd -T 查看最终生效配置。
13. 从 VM1 再次登录 VM2，验证配置后 SSH 服务仍可正常使用。
14. 在 VM2 的 auth.log 中确认登录日志正常记录。

二、实验环境

本阶段沿用阶段 0 和阶段 1 的实验环境。

1. VM1：SSH-VM1
   - 角色：管理端
   - 系统：Ubuntu Desktop
   - Host-only IP：192.168.45.101
   - 用途：通过 SSH 登录 VM2，后续部署 Flask SSH 管理平台

2. VM2：SSH-VM2
   - 角色：SSH 目标机 / 被管理端
   - 系统：Ubuntu Server
   - Host-only IP：192.168.45.102
   - 用途：运行 OpenSSH Server、保存 auth.log、后续部署 Fail2ban

3. VM3：SSH-VM3
   - 角色：攻击端
   - 系统：Kali Linux
   - Host-only IP：192.168.45.103
   - 用途：后续执行弱口令攻击和私钥泄露验证

本阶段主要操作对象为 VM2，VM1 仅用于 SSH 登录验证。

实验账号：

- 用户名：testuser
- 密码：123456
- SSH 目标地址：192.168.45.102
- SSH 端口：22

三、阶段前提

进入阶段 2 前，阶段 1 已完成以下工作：

1. VM2 已安装 openssh-server。
2. VM2 的 ssh 服务处于 active running 状态。
3. VM2 的 22 端口正在监听。
4. VM2 已创建 testuser 实验账号。
5. VM1 可以通过 ssh testuser@192.168.45.102 登录 VM2。
6. VM2 的 /var/log/auth.log 中可以记录 Accepted password 登录日志。

四、操作过程

1. 确认 SSH 服务状态

在 VM2 上执行：

sudo systemctl status ssh --no-pager

验证结果：

SSH 服务处于 active (running) 状态，说明阶段 1 安装并启动的 OpenSSH Server 正常运行。

2. 确认 22 端口监听状态

在 VM2 上执行：

sudo ss -tlnp | grep ':22'

验证结果：

可以看到 sshd 正在监听 22 端口，说明 SSH 服务对外提供连接能力。

3. 备份 SSH 主配置文件

在 VM2 上执行：

sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak_stage2

随后执行：

ls -l /etc/ssh/sshd_config*

验证结果：

可以看到 /etc/ssh/sshd_config.bak_stage2 备份文件。这样如果后续配置错误，可以通过备份文件恢复 SSH 配置。

4. 检查 sshd_config 是否支持 Include 配置片段

在 VM2 上执行：

grep -n '^Include' /etc/ssh/sshd_config

实际输出：

12:Include /etc/ssh/sshd_config.d/*.conf

说明当前 VM2 的 OpenSSH 配置支持读取 /etc/ssh/sshd_config.d/ 目录下的 .conf 配置片段。

因此，本阶段采用独立配置片段方式，不直接大幅修改 /etc/ssh/sshd_config 主配置文件。

5. 创建实验用 SSH 配置片段

在 VM2 上执行：

sudo nano /etc/ssh/sshd_config.d/99-lab-basic.conf

写入以下内容：

PermitRootLogin no
PasswordAuthentication yes
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 6
LogLevel VERBOSE

保存并退出 nano：

Ctrl + O
Enter
Ctrl + X

6. 查看配置片段内容

在 VM2 上执行：

sudo cat /etc/ssh/sshd_config.d/99-lab-basic.conf

验证结果显示配置片段内容如下：

PermitRootLogin no
PasswordAuthentication yes
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 6
LogLevel VERBOSE

说明实验用 SSH 基础安全配置已经写入完成。

7. 检查 SSH 配置语法

在 VM2 上执行：

sudo sshd -t && echo "sshd config syntax OK"

验证结果：

sshd config syntax OK

说明 SSH 配置语法正确，可以安全重启 SSH 服务。

8. 重启 SSH 服务

在 VM2 上执行：

sudo systemctl restart ssh

然后查看服务状态：

sudo systemctl status ssh --no-pager

验证结果：

SSH 服务重启成功，并保持 active (running) 状态。

9. 查看最终生效配置

在 VM2 上执行：

sudo sshd -T | grep -E '^(permitrootlogin|passwordauthentication|pubkeyauthentication|permitemptypasswords|maxauthtries|loglevel)'

预期结果如下：

permitrootlogin no
passwordauthentication yes
pubkeyauthentication yes
permitemptypasswords no
maxauthtries 6
loglevel VERBOSE

验证意义：

sshd -T 显示的是 OpenSSH 最终生效配置，比单纯查看配置文件更可靠。因为 OpenSSH 可能通过 Include 引入多个配置文件，直接查看 /etc/ssh/sshd_config 不一定能反映最终生效状态。

10. 从 VM1 测试登录 VM2

在 VM1 上执行：

ssh testuser@192.168.45.102

输入密码：

123456

验证结果：

VM1 成功登录 VM2。

登录后执行：

whoami
hostname

whoami 输出为 testuser，说明配置后 testuser 仍然可以通过密码方式登录 VM2。

测试完成后退出：

exit

该验证说明阶段 2 的 SSH 安全配置没有破坏后续实验所需的密码登录能力。

11. 在 VM2 查看登录日志

在 VM2 上执行：

sudo grep 'Accepted password' /var/log/auth.log | tail -n 10

验证结果：

可以看到类似记录：

Accepted password for testuser from 192.168.45.101 port XXXXX ssh2

说明 VM1 登录 VM2 的行为被 VM2 正常记录到 auth.log 中，后续平台日志查看和攻击检测功能可以基于该日志实现。

五、关键配置说明

1. PermitRootLogin no

含义：

禁止 root 用户通过 SSH 远程登录。

作用：

降低高权限账号被直接暴力破解或滥用的风险。后续远程管理应使用普通用户 testuser 登录，再根据需要使用受限 sudo 或固定命令进行管理。

2. PasswordAuthentication yes

含义：

允许使用密码进行 SSH 登录。

作用：

本阶段保留密码登录，是为了后续弱口令暴力破解实验。testuser 的密码 123456 将作为弱口令实验的目标凭据。

注意：

PasswordAuthentication yes 并不是最终防御状态。后续完成弱口令攻击验证后，会在防御阶段将其修改为 no，以验证禁用密码登录对暴力破解的防御效果。

3. PubkeyAuthentication yes

含义：

允许使用公钥认证登录 SSH。

作用：

为后续禁用密码登录、私钥泄露实验、密钥轮换实验做准备。后续 VM1 会生成密钥对，并将公钥添加到 VM2 的 authorized_keys。

4. PermitEmptyPasswords no

含义：

禁止空密码用户通过 SSH 登录。

作用：

防止系统中存在空密码账号时被远程登录，属于基础安全配置。

5. MaxAuthTries 6

含义：

每个连接允许的最大认证尝试次数为 6。

作用：

当前阶段保持为 6，保证实验兼容性。后续可以在防御加固阶段将其调整为 3，以减少单连接内的认证尝试次数。

6. LogLevel VERBOSE

含义：

提高 SSH 日志详细程度。

作用：

便于后续在 /var/log/auth.log 中观察认证相关日志，包括 Accepted password、Accepted publickey、Failed password 等记录，为平台日志分析和攻击实验取证提供基础。
